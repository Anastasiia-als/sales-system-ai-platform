# Календар бронювання консультацій — Google Calendar Appointment Schedule

Версія: 0.1 · Дата: 2026-09-01 · Статус: підготовлено технічно; активація — після створення розкладу власницею (ручна дія в її акаунті).

## Рішення власниці (2026-09-01)

- MVP-інструмент: **Google Calendar Appointment Schedule** на пошті `a.zaporozhetswork@gmail.com`.
- Нічого не купувати. Якщо потрібна функція виявиться платною — зупинитись і запропонувати альтернативу.
- Воронка: безкоштовна заявка → коротка кваліфікація → після підтвердження — бронювання **платної консультації 7 000 грн**.

## Доступність без платної підписки (перевірено за документацією Google)

Базові Appointment Schedules доступні **безкоштовно** для особистих Google-акаунтів (@gmail.com): одна активна сторінка бронювання, вибір слотів, автоматичне створення подій у календарі. Преміум-функції (кілька розкладів, email-нагадування, перевірка оплати через Stripe, брендування) вимагають Google Workspace / Workspace Individual — **вони для MVP не потрібні**.

`TO_CONFIRM (ручна перевірка власниці):` у Google Calendar акаунта `a.zaporozhetswork@gmail.com` → Settings → Appointment schedules → Create. Якщо кнопка доступна і розклад створюється без запиту оплати — MVP підтверджено. Якщо Google запропонує підписку — не купувати, повідомити; альтернатива: власна логіка слотів на Supabase (таблиця + RPC, ~1 день роботи) або безкоштовний тариф Calendly (1 тип події).

## Цільовий флоу (після активації)

1. Клієнт залишає безкоштовну заявку на `#/consultation` (жодної оплати на цьому кроці).
2. Заявка потрапляє в `marketing_leads` (статус `new`) → кваліфікація власницею (статус `qualified` / `disqualified` + причина).
3. Кваліфікованому клієнту надсилається персональне посилання на Appointment Schedule (бронювання слоту) → статус `booked`, подія `book_call`.
4. Оплата 7 000 грн (спосіб — за рішенням щодо еквайрингу) → статус `consultation_paid`.
5. Консультація проводиться; далі — `proposal_sent` → `won`/`lost`.

## Технічна підготовка (вже в коді)

- `js/marketing/marketing-config.js` → `APPOINTMENT_SCHEDULE_URL`: порожній рядок = функція вимкнена. Після створення розкладу сюди вставляється публічний URL сторінки бронювання.
- Подія `book_call` описана в tracking plan; фіксується вручну власницею через RPC `update_marketing_lead_status(lead_id, 'booked')` (автоматичний webhook від Google Calendar на базовому тарифі недоступний — синхронізація ручна або через періодичну перевірку календаря на наступних етапах).
- Поля `booked_call_at`, `call_show_status` (booked/showed/no_show) вже в схемі `marketing_leads`.

## Що НЕ робиться без окремого погодження

- Покупка Workspace/Calendly підписок.
- Автоматичні email/SMS-нагадування клієнтам.
- Інтеграція оплати в сторінку бронювання.
