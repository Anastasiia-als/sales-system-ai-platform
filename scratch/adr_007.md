
## ADR-007: Phase 6A - Immutable Project Template Versioning

### Context
To support One-Click Project Creation, FIRSTWIN requires Project Templates containing predefined stages, milestones, tasks, documents, and meetings. We must prevent retroactive changes to active projects when a template is modified, and ensure that templates can be safely updated without breaking historical data or creating inconsistencies for in-flight projects.

### Decisions

#### 1. Immutable Relational Versioning (Schema Snapshotting)
Instead of large JSON blobs or mutating published templates, we implement a hybrid relational approach. Templates are partitioned into `project_templates` (header) and `template_versions` (state snapshot). All content (tasks, milestones, etc.) belongs to a specific `version_id`.

#### 2. DRAFT vs. PUBLISHED Lifecycle
- `draft`: Modifiable version (Builder UI). Can be freely edited.
- `published` (`is_locked = true`): Frozen snapshot used for generating active projects.
When a template requires changes, the user publishes a new version, automatically locking the old published version and transitioning it to `archived`. 

#### 3. Zero Retrofit Migration
Templates generate independent, detached clones of the relational tree (stages, milestones, tasks) in the active project tables. Projects are strictly bound to the snapshot `template_version_id` they were generated from. Changes to newer template versions do not cascade to existing projects.

#### 4. Idempotent Materialization RPC (`create_project_from_template`)
To ensure complete generation or total rollback without partial insertions, project generation is executed entirely within a PL/pgSQL atomic transaction using an `idempotency_keys` guard. Relative day offsets in the template are deterministically mapped to the new project's start date.

### Consequences
- Guarantees 100% integrity of historical project structures.
- Allows templates to evolve naturally without fear of breaking running projects.
- Provides strong auditing via `template_audit_events` tied to specific `template_version_id`s.
